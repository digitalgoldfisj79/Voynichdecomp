# VBM Joachim Exact v9 — Q2 synthetic global-codebook identifiability

Date: 2026-09-01
Branch: `experiment/vbm-joachim-exact-v9-20260901`
Status: **FROZEN BEFORE Q2 OUTPUT**

## Motivation

Q1 measures the evidential value of fitting a fresh VBM dictionary to an already-chosen sentence. It does not test the only form of VBM that could become evidential: one reusable bridge/nucleus dictionary learned without the target plaintext and transferred unchanged.

Q2 therefore asks an instrument question before any Voynich language fit:

> If text really is generated by the source-faithful VBM architecture with one global codebook, can a blind train-only solver recover that codebook and transfer it to untouched lines, while rejecting fresh-key and stable non-language adversaries?

If the answer is no, the global-codebook route is not presently identifiable and no Voynich decode is permitted from this branch.

## Representation

The factor representation is exactly the Q0b/Q1 representation:

`N0, B0, N1, B1, ..., B(B-1), NB`

- `B` is a bridge surface type with a global value in `{a,e,i,o,u}`.
- non-empty `N` is a nucleus surface type with one global consonant-run value of length 1–5.
- empty nuclei emit the empty string and require no dictionary entry.
- line edges emit nothing beyond their nucleus values.
- no contextual, folio-specific, hand-specific, or line-specific values are allowed in a global positive.

Q2 operates on factor streams, not reconstructed EVA tokens. This isolates identifiability of the proposed value system from graphical tokenization issues already fixed in Q0b.

## External language material

Synthetic plaintext and language models use deterministic `wordfreq`-based German (`DE`) and Italian (`IT`) banks. These modern banks are instrumental controls only; no historical-language claim is made.

For each language, independent deterministic banks are used for:

1. language-model training;
2. synthetic plaintext generation.

No plaintext substring used to generate a synthetic replicate is used to train its scoring language model.

The language model is a smoothed character 4-gram model over lowercase ASCII letters, without spaces.

## Candidate value inventory

For each language, the admissible nucleus values are the 32 most frequent non-empty consonant runs of length 1–5 in the language-model training bank. Empty is structurally known and excluded from the dictionary search.

All five vowels are admissible bridge values.

Synthetic positive plaintext windows are accepted only when every non-empty consonant run lies in the frozen 32-run inventory for that language. This gives the blind solver the true value inventory but not the assignments.

## Synthetic codebook

Each global positive uses:

- 30 bridge surface types, six homophones allocated to each vowel;
- 96 nucleus surface types, three homophones allocated to each of the 32 consonant runs.

Within each homophone class, emissions are drawn from a fixed replicate-specific Dirichlet distribution, producing unequal type frequencies while preserving one reusable mapping.

Each replicate contains 120 pseudo-lines with 8–14 bridge events per line, sampled from the independent plaintext bank at consonant-run boundaries.

Frozen split:

- lines 0–59: FIT;
- lines 60–79: SELECT;
- lines 80–119: HOLDOUT.

The split is generated before encoding and never changed after seeing results.

## Families

Positive families:

- `DE_GLOBAL`: German plaintext, one global codebook.
- `IT_GLOBAL`: Italian plaintext, one global codebook.

Binding negative/adversarial families:

- `DE_FRESHLINE`: German plaintext but a newly permuted codebook for every line.
- `IT_FRESHLINE`: Italian plaintext but a newly permuted codebook for every line.
- `MARKOV1`: stable first-order surface Markov process fitted to a global-positive surface stream, generated with the same line lengths and N/B alphabets. This is binding because v8 prequential compression failed specifically on a stable Markov1 adversary.
- `SHUFFLED_GLOBAL`: a global-positive stream with nucleus positions shuffled among nucleus positions and bridge positions shuffled among bridge positions independently within each pseudo-line, preserving alphabets and marginal type counts while destroying plaintext order.

No negative is given a hidden 'truth mapping' recovery score; its role is false-positive rejection by held-out language advantage and learned-map stability.

## Blind solver

For each candidate language separately:

1. initialize every bridge type to one of five vowels and every nucleus type to one of the language's 32 consonant runs using deterministic seeded random assignments;
2. decode FIT lines under the current dictionary;
3. maximize total smoothed character-4-gram log probability by coordinate ascent over dictionary entries;
4. for a bridge entry, test all five vowels;
5. for a nucleus entry, test all 32 consonant runs;
6. only lines containing the changed surface type are rescored;
7. use three deterministic random restarts and up to five coordinate passes per restart; retain the highest FIT objective;
8. no HOLDOUT line participates in fitting.

Language selection:

- fit DE and IT dictionaries on FIT only;
- score SELECT under each frozen FIT dictionary;
- choose the language with the higher SELECT per-character log probability;
- refit the selected language dictionary on FIT+SELECT from three new deterministic restarts;
- freeze it and score HOLDOUT exactly once.

Unseen HOLDOUT surface types use deterministic language-frequency defaults and are counted as unseen. No new mapping is learned on HOLDOUT.

## Primary statistics

For the selected language:

`HOLD_LM` = per-character log probability of decoded HOLDOUT under the selected fixed 4-gram LM.

`RAND_HOLD_LM` = median HOLDOUT score under 20 deterministic random dictionaries drawn from the same value inventories.

`HOLD_ADV = HOLD_LM - RAND_HOLD_LM`.

`STAB` = occurrence-weighted exact dictionary agreement between two independent dictionaries fitted to alternating halves of FIT+SELECT, evaluated over surface types occurring in HOLDOUT.

For global positives only:

`REC_B` = occurrence-weighted exact bridge-value recovery on HOLDOUT.

`REC_N` = occurrence-weighted exact non-empty nucleus-value recovery on HOLDOUT.

`REC_CHAR` = exact decoded-character recovery on HOLDOUT.

`LANG_OK` = whether DE/IT selection matches the generating language.

Also report seen-surface occurrence coverage in HOLDOUT separately for bridges and nuclei.

## Smoke

One replicate per family with one restart and two coordinate passes is nonbinding. Smoke exists only to catch implementation/runtime failures. It cannot qualify the instrument.

## Formal CAL

Three fresh replicates per family, full solver.

CAL can qualify only if all of the following hold:

1. at least 5/6 global-positive replicates have `LANG_OK=true`;
2. at least 5/6 global-positive replicates have `REC_CHAR >= 0.50`;
3. at least 5/6 global-positive replicates have both `REC_B >= 0.70` and `REC_N >= 0.40`;
4. the minimum global-positive median-by-family `HOLD_ADV` exceeds the maximum negative/adversarial median-by-family `HOLD_ADV`;
5. the minimum global-positive median-by-family `STAB` exceeds the maximum negative/adversarial median-by-family `STAB`.

If (4) and (5) separate, freeze:

- `TAU_ADV` at the midpoint between those two family-median extrema;
- `TAU_STAB` likewise.

If either statistic is nonseparable, Q2 closes at CAL and no Voynich language fit is run.

## Untouched VAL

Three new replicates per family.

Pass only if:

- at least 5/6 global positives exceed both `TAU_ADV` and `TAU_STAB`;
- each positive family passes at least 2/3;
- all 12 negative/adversarial replicates remain below at least one of the two thresholds (zero joint false positives);
- at least 5/6 global positives have `LANG_OK=true`;
- at least 5/6 have `REC_CHAR >= 0.50`;
- at least 5/6 have `REC_B >= 0.70` and `REC_N >= 0.40`.

Any MARKOV1 joint false positive fails validation.

## Voynich firewall

Q2 synthetic qualification opens no Voynich H1/C1 data and performs no Voynich language fit.

If and only if Q2 passes CAL+VAL, a separate Q3 protocol may be frozen for the existing Q0b TRAIN -> INTERNAL_HOLDOUT transfer. Q3 must retain explicit codebook description cost and must not open C1 unless its own frozen gate is passed.

## Closeout

- Synthetic CAL failure: close Q2 as `GLOBAL_CODEBOOK_NOT_IDENTIFIABLE_WITH_CURRENT_SOLVER` or `ADVERSARIAL_NONSEPARABLE`.
- Synthetic VAL failure: same closeout, with untouched failure retained.
- CAL+VAL pass: instrument qualified for a separately preregistered Voynich TRAIN/HOLDOUT test; this is not evidence that Voynich is VBM.

No solver hyperparameter, candidate-run count, family definition, threshold gate, or language model may be changed after formal CAL begins.
