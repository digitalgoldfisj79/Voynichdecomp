Frozen: 2026-09-07, before any v2 Stage-B pilot outcome.

## Why v2 exists

v1 is permanently BLOCKED. Its untouched validation showed that four broad source classes are highly separable after merging `working_set_only` and `line_reset_r64`, while that one pair is unresolved. v1's OOD gate was also invalidly optimistic in development because the same observations were used to fit and calibrate the 100-dimensional Mahalanobis envelope.

v2 is therefore not a threshold repair. It decomposes identification into two distinct assays.

## Stage A — broad source gate

The broad classes are:

1. `base_local = working_set_only OR line_reset_r64`
2. `r64_exact`
3. `refractory_exact`
4. `family_persistence`

The existing v1 20 directional features and corrected v1 development fit are reused. The manuscript posterior is collapsed by summing the working-set and line-reset posterior probabilities. There is no posterior-confidence abstention.

OOD is rebuilt prospectively: a broad-class Ledoit-Wolf envelope is fitted on v1 development, while the threshold is set from the *separate* v1 calibration panel by a higher split-conformal 95% order statistic. The already-seen v1 validation panel is not confirmation for v2. Fresh v2 validation is mandatory.

## Stage B — working-set vs physical-line-reset R64

Stage B uses the exact pinned RegionalModel probability model. The only change between the page and line candidate models is the state reset policy:

- page R64 clears `page_seq` only on page change;
- line-reset R64 clears `page_seq` on physical line change.

`RegionalModel.prob()` invokes `state.boundary(r)` before every event, so this is a faithful state-only comparison.

The inherited lambda grid is:
`0, .005, .01, .02, .03, .04, .06, .08`; `MU=.0009`.

Three held-out likelihood features are measured in bits/token:

- line-reset gain over lambda-zero;
- page-R64 gain over lambda-zero;
- line-reset advantage over page-R64.

The recurrence features target the mechanism's actual horizon, unlike v1's adjacent-only boundary contrast. Exact recurrence is partitioned into same-line versus cross-line opportunities for lags 2–5, 6–16, and 17–64. A second cache-hit statistic asks whether the current token occurs anywhere 2–64 events back within the current line versus across earlier lines. Every statistic is compared with 64 deterministic within-page order permutations that hold the line-position skeleton fixed.

Both R0 canonical tokens and R1 repeated-glyph-collapse representations are evaluated.

## v2 development pilot

The first v2 data are only 20 fresh working-set and 20 fresh line-reset manuscripts. They are development data, not qualification data.

A representation advances only if either:

- at least one prespecified Stage-B feature reaches >=3 matched-null SD, or
- fixed-C=1 five-fold grouped-CV binary accuracy reaches >=80%.

If either representation fails this development go gate, v2 Stage B is blocked and no fresh confirmation or target run occurs.

If both pass, development may be expanded to 40/source, after which the fixed five-feature classifier described in the manifest is frozen for fresh confirmation.

## Confirmation gates

Stage A fresh validation: >=90% recall per broad class, >=95% macro recall, <=10% abstention per broad class, all broad pairs positive and >=2 null SD, both representations.

Stage B fresh validation: >=80% recall per source, >=85% macro recall, positive true-class margin >=2 null SD, both representations.

Unknown controls: each must be rejected >=80% with positive >=2-null-SD OOD separation in both representations.

Power reporting for line-reset lambda is mandatory.

## Target seal

Voynich is inaccessible to v2 until every required gate passes. v1 validation, calibration and diagnostics may guide v2 design but can never count as v2 confirmation.
